# 2026-09-17: Experiment Attempting to Enforce ML-KEM on Istio

**Objective:** Force Envoy sidecar proxies to negotiate Post-Quantum Cryptography (PQC) by eliminating the classical X25519 fallback curve.
**Methodology:** Deploy an `EnvoyFilter` strictly specifying `ecdh_curves: ["X25519MLKEM768"]` on both client (k6) and server (httpbin).
**Result:** 100% of k6 requests resulted in TLS handshake failure (`http_req_failed: 100.00%`). Prometheus telemetry counters for `ssl.curves` remained at 0 increment.
**Thesis Finding:** Official Istio distribution images lack BoringSSL post-quantum compilation flags or runtime curve mappings for pure ML-KEM-768 without classical fallback. Empirical evidence demonstrates that default Istio Envoy sidecars currently reject TLS negotiation when classical X25519 is disallowed.
**Raw Evidence:** Captured connection abort error logs preserved in `04_results/Summary/pqc_failure_report_*.txt`.
